# Duplicate workbench operations — measured 2026-09-21

This is an audit, not a reconciliation. The kernel addresses an operation by
`(source, id)`, so every implementation below remains independently reachable.
No workbench module was changed.

The observations are executable in
`lib/kernel/duplicate-probe.test.ts`. Each pair received the same semantic input,
translated only where the two existing forms use different field names. The test
will fail if these observations drift.

| ---------------------- | -------------------------------------- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `csv-to-json`          | `developer-data`, `spreadsheet`        | Header CSV with a quoted comma                 | Byte-identical formatted JSON; one object with `name: Ada` and `note: hello, world`.                                                                                             | Both are correct for this case. Neither is silently aliased.                                                                                                                                             |

## Decision boundary

The four byte-identical pairs are duplication of implementation or surface. The
other five deliberately expose different output contracts, even when their core
facts agree. The kernel therefore does not call `getOperation(id)` for a duplicate;
it requires `getOperation(id, source)` and reports the available sources when the
caller omits one.

The owner and the converter/notation lane can use this evidence to rename,
consolidate or retire entries later. Phase 1 changes none of them.
